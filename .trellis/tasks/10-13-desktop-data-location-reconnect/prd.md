# 客户端数据目录重命名后重新定位与防覆盖

## 目标

修复 Electron 客户端在用户手动重命名自定义数据目录后，仍按旧路径启动并静默创建空目录的问题。客户端应在打开工作台前要求重新定位原数据目录；未完成定位不得打开新空库造成“项目消失”。

## 已确认现象

- 指针 `data-location.json` 仍保存旧的自定义目录路径。
- 用户重命名真实数据目录后，旧路径不存在。
- 当前 `isDirWritable()` 会递归创建不存在的目录，导致旧路径变成新的空数据目录。
- 新建目录中的 `projects`、`projectSummaries`、`images` 均为空，无法恢复旧项目。
- 用户反馈使用 Electron 客户端，不能以 Web 端行为替代验证。

## 需求

- 启动时检查自定义数据目录必须是已存在且可识别的数据目录；检查不得创建缺失路径。
- 旧路径缺失、不可用或指针无效时，在打开工作台前展示原生目录定位对话框；用户选择实际数据目录本身后更新指针，不复制、不删除、不合并数据库文件。
- 取消定位则退出，不回退默认空库，不根据目录名称或单一候选猜测数据归属。
- 存储设置中允许用户选择已有数据目录本身；选择已有目录时直接连接，选择普通父目录时保留现有“父目录/证据采集数据”迁移行为。
- 迁移目标已存在有效数据时不得把另一套 IndexedDB 目录直接复制覆盖；必须拒绝并提示用户先选择正确目录。
- 不引入外部值文件自动反序列化或推测项目结构；本次验证明确区分路径修复与原库记录损坏。

## 验收标准

- `verify:data-location` 覆盖：旧路径缺失时不创建且启动阻塞；目录重新选择成功、取消、无效目录、权限错误；已有数据目录选择直接连接；有效目标冲突时拒绝迁移；源消失和目录嵌套拒绝复制。
- Electron 隔离启动验证：旧路径为空/不存在时不会出现项目数为 0 的伪正常状态；重连到真实目录后能读到项目和图片 store。
- 重连使用隔离 Electron 验证，保留项目、摘要和图片的原有内容；对原包另行只读核对，不宣称路径修复能凭空恢复损坏记录。
- `npm run build`、`npm run verify:data-location`、相关 Electron 验证和 `git diff --check` 通过。
- 不改用户原数据目录，不执行删除、迁移或提交之外的不可逆操作。
