# 客户端数据目录重连验证与交付

## 实现结果

- 自定义数据路径失效、指针损坏或待直连目录失效时，正式主进程在创建工作台前要求重新定位。取消或失败退出，不创建旧路径、不回落到默认空库。
- 选择已有数据目录本身仅更新路径，重启后读取；普通父目录走固定子目录迁移，不猜测候选。源失效、目标占用、目录嵌套拒绝复制。
- 重连保留历史备份，清理保护当前数据目录及其祖先。存储设置区分直连和迁移反馈。

## 验证证据

- `npm run verify:data-location`：70/70 通过，包括配置损坏、权限错误、配置保存失败、待直连目录消失及备份保护。
- `npm run build`：TypeScript、Vite 与 Service Worker 构建通过；保留既有的大 chunk 提示。
- `node scripts/verify-data-location-electron.mjs`：五组正式 main/preload 隔离回归通过。合成原生 IndexedDB 在退出后真实改名；取消与无效目录 windowCount=0；恢复后系统列表可见、打开后图片实际显示并解码；再次启动使用持久指针且数据一致；有效空库通过正式 IPC 直接重连。
- `node --check`：宿主和 Electron 测试入口语法通过。
- `git diff --check`、Trellis 上下文工件校验通过。
- 独立 trellis-check 派遣因供应商凭证不可用未启动；生命周期、IPC、类型与失败分支由主会话审查，无独立子代理证据。

0.11.2 发布本任务的数据目录重连与迁移防覆盖修复，未完成的批量导出、弹窗样式与旧模板预设引导不纳入本版。已从暂存区导出实际发布源码，在该副本上重新通过目录回归 70/70、`npx tsc --noEmit`、生产构建和正式 Electron 五组回归。推送版本标签后由现有 CI 生成 EXE 与 Web ZIP；用户自行查看构建和发布结果。

## 用户操作

1. 退出旧客户端，运行正式版。
2. 如出现重新定位提示，选择改名后的真实数据目录本身（内含 IndexedDB），不选父目录。
3. 如旧版已生成有效空库，进入存储设置、更改目录，直接选择真实数据目录，确认连接并重启。
4. 检查列表、打开系统及图片；路径修复只读取该目录中的现存有效记录。

## 能力边界

验证使用合成隔离库，原生目录选择器由受控选择替代；用户现场运行尚未验证。路径修复不解析外部值文件，不会自动补回已缺失的项目文档或图片索引。需要恢复的数据通过私下交付的恢复包另行导入，或连接解压后的恢复数据目录。

真实用户资料、离线恢复脚本及其报告只保存在 Git 忽略的 runtime 内，不进入公开提交和 Release。
