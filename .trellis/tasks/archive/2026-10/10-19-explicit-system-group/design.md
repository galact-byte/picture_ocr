# 显式创建类型与独立系统转组设计

## 模块边界
`ProjectGroupDialog` 表达用户选择并做表单反馈，`ProjectList` 编排保存和定位，`db.ts` 负责校验及真实原子写入，`projectListViews` 继续只按 groupId 分类。禁止靠解析展示名称把一个文档假装成多个系统。

## 创建契约
- 新建表单加入原生互斥单选“单系统 / 系统组”，不是两个可同时勾选的 checkbox；使用既有表单样式和可见标签，支持 Tab/方向键。
- 新建打开时按当前列表确定初始类型；用户手动改变后，预设异步读取/引导完成不得重置其选择或已填内容。关闭后下次新建重新按当前列表初始化。
- 表单提交增加仅用于 UI/调用的 `creationType: 'independent' | 'group'`，不写入文档、不新增 schema 字段。
- 选择单系统：名称按已有新建规则解析后必须恰好一个；多个时在字段旁提示选择系统组，保留所有输入，不自动变类型或丢弃多余名称。
- 选择系统组：允许一个或多个名称，均写真实 ProjectGroup 和带 groupId 的系统。复用 splitSystemNames 去重与既有模板快照规则，不要求先填写两个名称。
- 沿用既有元数据必填和 profile 校验，不新增组名必填；同步修正现有空列表中“必须填写多个名称才创建组”的过时提示，不增加额外说明。

## 独立系统编辑追加契约
- 保持现有编辑入口，独立系统的名称输入允许使用逗号、顿号或换行追加名称；仅有普通名称内空格不能触发转组。复用拆分/去重核心，只扩展可控制分隔规则，不另写一套不一致解析器。
- 拆分结果只有一个时仍为普通编辑。多个时，第一个名称对应原系统，后续名称各创建一个空白新系统；表单初始值为原名称，因此正常追加保留原数据归属。
- 原系统 ID、createdAt、profile、分类、资产、检查项、图片引用与字节保持；仅更新用户本次编辑的元字段、原系统名称、groupId 和 updatedAt。
- 新组元数据来自已校验的本次编辑值，profile 沿用原系统配置；新增系统采用同一组 profile 与表单已加载的新建分类模板，不复制原资产。
- 已在组中的系统编辑仍只改该系统名称，不支持通过名字再次建组；本轮不提供拆组、合并现有组或移动已有系统功能。
- 不在后台自动拆分以前保存过的逗号名称；仅用户再次提交独立系统编辑时执行。组内添加系统的既有行为不随本次扩展。

## 数据层接口与事务
新增一个窄职责入口（例如 `convertIndependentSystemToGroup`），参数包含 sourceId、编辑值、拆分名称、已加载预设快照及可用于陈旧检测的源版本。

1. 在事务外校验名称数量/去重和输入结构，不在写事务中 await 网络或另开预设读取。
2. 以 `trackWrite` 包裹一个 `projectGroups + projects + projectSummaries` 读写事务。
3. 在事务内重新读取源文档及摘要，确认存在、未归档、仍独立且未发生会覆盖编辑的陈旧版本变化；异常时 abort，提示重新读取。
4. 从最新源文档构造原系统的新归属，仅改必要字段，禁止用旧 UI 整份快照覆盖源资产。
5. 同事务写组、原系统、所有新增系统及对应摘要；任一 put/校验失败整体 abort。图片 store 不需要写入，因为原 projectId 未改变。
6. 超时请求 abort 后等待实际 complete/abort，避免“报失败但后台实际已建组”导致用户重试重复创建。释放连接和 pendingWrites 计数，以真实终态结算。
7. 返回目标组 ID 与原系统 ID，事务 complete 后才关闭表单和触发元数据保存回调。

创建组路径同步检查 trackWrite、onabort 和连接清理是否满足新增行为，必要时局部补齐，不重构其他数据库写路径。

## 导航与异步失败
- 沿用 pendingReveal：单系统定位独立列表；新组与转组定位组列表、清目标搜索、展开目标组并找到原系统。
- 保存成功而刷新失败时保留待定位目标，显示加载失败重试，不重走创建/转组；取消和保存失败不跳列表。
- 防重复提交；在忙碌阶段禁用提交和会产生冲突的类型切换。卸载/延迟结果不得重开旧弹窗。

## 兼容性与回滚
- 无 DB 升级、无格式变更；旧版已支持真实组与 groupId，能读取本次创建的组。
- 原图片键 `${projectId}:${imageId}` 不变，旧 ZIP/加密包结构不变；单系统包按原设计不携带完整组归属，不把单包往返等同于组备份。
- 已完成的真实转组是用户数据修改，回退代码不自动拆组；失败事务自动回滚，成功数据不做无授权逆操作。

## 影响文件
ProjectGroupDialog、ProjectList、db.ts；必要的局部表单类型及已有验证脚本。projectListViews 只做回归，不为此改变分类依据。共同修改文件在旧等保引导子任务 GREEN 后串行整合。
