# 技术设计

## 边界与数据流
- `preset.ts` 根据旧版历史源码已有分类 ID、类型组合及兼容报告配置确认旧等保模板（只保存结构签名，不复制分类名称和检查项内容），复用 `presetFromProject` 提取模板；比较多个模板的分类、检查项、profile，任一不同则不推荐。
- `db.ts` 先在 settings 只读事务查询默认预设与引导结果；无结果时通过摘要 profile 预筛，只有全部符合旧配置才按主键逐条读取 projects。只提取分类与 profile，不 hydrate 图片，不写项目，读取结束即释放文档。
- 检测只从新建表单 create-group / create-independent 初始化触发；添加系统不触发。不挂到 `ProjectList.refresh`，不改变首屏的摘要查询契约。
- `ProjectGroupDialog` 内同一个可访问弹窗先展示引导，两项选择提交后显示新建表单。沿用选择写入提取的预设并设置默认；通用选择仅记引导完成。当前共用新建入口覆盖多系统与独立系统，`NewProjectDialog` 未被实际使用。
- 写入在 settings 单事务内重新检查默认预设和引导状态；其他窗口已设置默认时返回其当前值，不覆盖。事务 oncomplete 才推进表单和成功提示，onabort 保留引导。

## 持久化与兼容
新 settings key `legacyPresetOnboarding` 仅记录完成选择，不提高数据库版本、不更改旧文档或摘要结构。已保存默认预设时一律跳过引导，包括显示通用默认的显式选择。关闭引导不记录选择，下次新建可重试；确定选择后跨重启保持。

## 失败与生命周期
读取错误进入现有可重试错误状态，阻止未确认模板时保存新项目；保存错误保留弹窗及操作。初始化/提交通过代际 ref 拒绝关闭、切换与卸载后的过期 UI 更新。提交使用同步 ref 防重入，保存中禁用关闭和重复点击。引导按钮自动聚焦、Tab 闭环、Escape 取消及关闭后焦点恢复均有双端键盘验证。

## 发布
数据目录修复已随 v0.11.2 发布，本任务进入下一正式版本。按实际源码差异分别核对预设引导、批量导出和已批准的弹窗样式；任何仍待验证的改动不得写为已完成。正式 release 构建从已提交源码生成，不能夹带客户端恢复数据、运行时目录或外置等保模板。只上传便携版 exe 与现有 Web ZIP，回读 release 正文及资产。
