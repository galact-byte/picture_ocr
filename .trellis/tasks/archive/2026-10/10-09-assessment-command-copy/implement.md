## 有序步骤

1. **内容核对**：按 `research/command-reference.md` 精读需要纳入的笔记和现场清单；保留各命令的执行环境与版本边界，剔除结论模板、整改命令及客户信息。首版四类和各来源平台均要覆盖，不用庞大脚本代替可复制的小段。
2. **Red**：新增 `scripts/verify-assessment-commands.mjs`，验证四类覆盖、唯一 ID、非空命令、单一环境、分组拼接、分类辅助匹配、搜索及跨平台隔离。先运行并记录因功能缺失导致的失败。不得仅断言源码含某字符串。
3. **Green**：加入静态命令目录及必要纯函数，使上述行为验证通过。来源记录同步维护，不把本地笔记路径作为运行时依赖。
4. **界面与增删改查**：实现弹窗与资产页入口，复用现有样式，处理焦点、搜索空态、选择重置、卸载与剪贴板错误。新增命令覆盖层及内容校验，验证内置编辑/隐藏、自定义新增/编辑/删除、刷新保留、存储损坏/拒绝以及未保存确认。生命周期由同一资产 ID 统一管理，避免显示与复制的数据错位。
5. **检查项关联**：先验证稳定 ID 绑定、项目/资产/检查项隔离、失效引用与存储异常，再实现标题旁展开区域和库内关联操作。共用最新命令内容，核对库内增删改、刷新、重命名/排序、跨窗口同步、粘贴目标不变，以及行内代码在窄内容区的滚动。
6. **真实验证**：加入 `scripts/verify-assessment-commands-browser.mjs`，复用现有 CDP 隔离浏览器工具，覆盖 Chrome 与 Electron 实际点击后剪贴板读回，以及局域网 HTTP 下的回退和双端离线查看。核对静态命令来源、环境、参数、版本、说明；查看三个宽度截图及键盘流程，检验操作前后项目证据数据不变，截图粘贴与检查项排序仍可使用。
7. **综合回归**：执行 Trellis 质量检查，将命令目录/复制/关联契约更新到相关 spec，补充 README 与变更记录。整理文件清单和验证证据；界面验收后进入提交阶段，依项目约定一次性审阅提交清单，不混入其他任务改动，不自行发版。

## 风险与回退点

- 数据内容最容易出现命令夹说明、版本混放、SQL 错误注释：先整理纯数据与内容验证，再写 UI。
- 非安全 HTTP 来源可能没有 Clipboard API：在同一点击同步尝试浏览器复制回退；失败可人工复制，不能只测 localhost。
- `dialogStyles.ts` 与其他弹窗处于另一任务的未提交状态：每次实施前复查；只依赖可用公共样式，不修改其他任务文件。
- 每一步可单独撤回本任务新增模块；`ContentArea.tsx` 只做局部入口接线。不得 reset、覆盖用户已有修改或改数据 schema。
