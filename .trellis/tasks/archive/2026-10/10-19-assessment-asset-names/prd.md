# 等保分类资产名称预设

## 目标与归属
父任务 `../10-19-preset-group-experience/` 的 R4：为使用等保分类的用户提供资产名称填写参照，不再让所有分类都只有核心交换机示例。

## 事实
`src/components/Sidebar.tsx:327` 所有 checklist 分类使用同一输入示例。实际资产由用户确认后经 ADD_ASSET 创建。详见父任务 research/current-behavior.md。

## 需求
- 按等保分类在空名称输入框内显示匹配的 placeholder 示例，至少覆盖“例如：xx机房”“例如：xx交换机”。
- 用户已确认只需示例：不作为实际输入值、不自动填入、不提供候选按钮或下拉选择，不增加任何操作步骤。
- 用户自行输入实际名称；不自动插入资产，不改变分类检查项与原有资产。
- 通用与自定义用途分类不强行展示等保专用内容；分类识别不能仅依赖当前全局默认名称，以免旧项目在切默认后失去参照。
- 仅调整既有输入框示例，不增加控件或解释性小字，不扩展持久化预设协议。

## 验收
- A1：物理环境与网络设备的空输入框分别显示机房和交换机示例，其余既有等保分类逐项检查。
- A2：显示示例时实际输入值仍为空，直接按 Enter 不创建示例资产；用户输入后按原流程仅创建一次并沿用当前分类检查项。
- A3：取消、空名称、键盘/焦点及输入失焦不误创建或丢失输入；旧资产不变。
- A4：通用分类、已改名的旧等保分类和未知自定义分类的回退行为正确。
- A5：隔离 Web/Electron 与三档布局/键盘检查通过。

仅作用于当前项目被确认采用等保核心分类的情况；按稳定分类 ID 与 type 匹配，分类改名仍适用，不读当前全局默认名。

| 分类 ID | 空输入框名称示例 |

| cat-physical | 例如：xx机房 |
| cat-network | 例如：xx交换机 |

沿用既有“资产名称 / 材料名称”语义，仅替换其中的例子；通用/未知分类保留既有回退，不增加帮助文案。
