# 等保预设与系统分组体验修正：集成设计

## 任务边界
父任务负责需求追踪、方案审阅与最终联合验收，不作为默认代码实现目标。详细设计分别位于：
- R1：`../10-19-legacy-preset-followup/design.md`。
- R2/R3：`../10-19-explicit-system-group/design.md`。
- R4：轻量任务，直接按 `../10-19-assessment-asset-names/prd.md` 中的交互、示例表和验证计划执行。
- R5：用户追加的窄屏工作台修复，边界与生命周期见 `../10-19-workspace-narrow-layout/design.md`。独立验证，保持 R1–R4 成果。

## 用户可见行为
| 需求 | 最终行为 |
| --- | --- |
| R1 | 列表出现后检测全等保旧库并一次性引导；用户同意后沿用最近等保项目模板作为新建默认，旧项目不动。 |
| R2 | 新建可选单系统/系统组，默认跟随当前列表；系统组允许先只有一个成员。 |
| R3 | 独立系统编辑中用逗号等追加多个名称，形成真实组；首个名称对应原系统并保留原证据，新增名称创建空白系统。 |
| R4 | 原输入框按等保分类显示灰色示例，无额外控件，不自动填写/创建资产。 |

## 数据流与共享契约
```text
摘要首屏 → 独立的延后等保核对 → 引导选择 → settings 原子保存 → 未来创建使用同一预设快照
当前列表 + 用户类型选择 → 创建表单 → db 原子创建 → 摘要刷新 → 定位正确列表/组
独立系统编辑追加 → db 事务内重读原文档 → 保留 ID 转组 + 新建空白成员 → 摘要刷新 → 展开目标组
项目自身等保分类 → Sidebar placeholder → 用户输入真实名称 → 原 ADD_ASSET 流程
```
- 项目分组真相仍是 ProjectGroup + groupId，不从名称或 UI 选择状态推导持久归属。
- 等保身份由合法核心分类 ID/type 判定，而非报告标题、当前全局预设名或完整模板文本相等。
- 字段示例由当前项目分类判定；改全局默认不影响已打开项目的示例。
- 不更改 DB_VERSION、预设 version=1、ZIP/加密包或图片键协议，无新依赖、IPC 或外部服务。

## 依赖与串行整合
1. R1 先实现，提供唯一的等保分类判据并调整 ProjectList/ProjectGroupDialog 引导生命周期。
2. R2/R3 在 R1 全绿之后实现，避免同文件并行编辑；其功能不要求有等保预设。
3. R4 复用 R1 分类判据，仅按约定表显示 placeholder；不新增另一套等保身份识别。
4. 父任务执行联合场景：全等保库进入列表 → 接受默认 → 从组页建单成员组 → 独立系统编辑追加转组 → 打开系统核对名称示例和真实证据。

## 失败和兼容性原则
- 显式 defaultPreset 或引导选择不能被后台判定覆盖；识别失败不自动选择通用。
- 文档与摘要一起写入；转组按源最新记录现读现改，原图片字节无需移动。
- 创建/转组成功但刷新失败只重试读取和定位，不重复写入。
- 已归档、已被删除/转组、陈旧编辑等状态明确拒绝，不造空白替代文档。
- 回退代码不降 DB 版本，不清用户设置，不自动拆分已成功创建的组。
- 对用户真实 Web 构建/缓存/存储状态尚无证据，本地隔离验证不能宣称已检查用户的浏览器。最终说明区分代码修复与用户现场结果。

## UI 与范围约束
功能型工具界面，沿用既有 slate/blue、普通弹窗样式和原生控件。仅新增所需类型 radio，其余不加解释性小字、候选控件、自动示例资产或无关设置。按 frontend-design 与 ui-ux-pro-max 的 Web 通用规则检查键盘、标签、焦点、触控目标与三档布局，不套展示页/移动原生重设计规则。
