# picture_ocr 通用化与预设系统

## 目标

将图片证据采集工具从固定等保场景改为通用工具；通过应用内导入预设恢复行业模板，桌面与 Web ZIP 共用实现。用户已确认总体方案并授权继续，任务创建已获授权。

## 已核实背景

- `src/data/defaults.ts:12` 实际包含 8 类：6 类环境/设备模板、管理层面、其他；并生成 8 个等保示例资产。应完整保留外置预设中的分类与检查项，而非按原描述误删后两类。
- `src/types/index.ts:73` 的项目文档保存自己的分类、检查项和资产，但没有报告/单位字段配置；旧数据无法还原从未存入文档的标题和文件名前缀。
- `src/utils/db.ts:382` 创建新文档；`:410` 归一化已有文档；`:1385` 当前对空分类回填内置分类，需区分明确空数组与缺字段。
- `src/utils/wordDocument.ts:172`、`:429` 固定报告标题；`src/utils/wordExport.ts:57`、`src/utils/exportImport.ts:116` 附近固定导出命名。
- `src/components/project-list/NewProjectDialog.tsx:32`、`ProjectGroupDialog.tsx:67` 固定要求单位；Sidebar 目前只有资产新增/改名，没有分类新增/改名。
- `electron/dataLocation.cjs:14` 与 `:29` 依赖既有数据目录及默认 userData 指针位置。通用化不得使旧桌面数据不可见。

## 需求与验收

| ID | 需求 | 可验证验收 |
|---|---|---|
| R1 | 内置通用模板；分类可新增/改名；检查项沿用模板编辑能力 | 全新库不出现等保模板或示例设备；分类改名后资产引用不变，重开后保留；新资产获得所属分类模板 |
| R2 | 预设包含分类、检查项、报告标题、文件名前缀、单位字段名及必填开关 | 合法 JSON 可在应用导入并持久保存为新建默认；重开仍生效；错误格式/版本/类型/重复 ID 给出中文错误且不改原默认 |
| R3 | 项目配置可编辑且独立于全局预设 | 新项目得到创建时快照；更换默认只影响随后新建；Word 标题及文档属性、ZIP/DOCX/加密包命名遵循项目配置；文件名不能包含路径或 Windows 非法字符 |
| R4 | 通用模式单位可选；等保预设名称为“单位名称”且必填 | 新建、编辑、组创建、组编辑、组内添加系统使用对应配置；未配置的旧项目继续要求单位；检查项必填规则不改变 |
| R5 | 已有项目内容不变；旧数据包及合并兼容 | 打开、编辑、保存不替换旧分类/检查项/资产/图片；ZIP 和加密包往返保留配置；合并保留目标配置；旧包走固定旧项目兼容规则；归档恢复不丢配置 |
| R6 | 当前项目可另存为预设 | 导出项目分类模板和配置的 JSON，不含实际资产、图片、单位值或项目身份；标题等字段可编辑后保存；导入该 JSON 能用于新建 |
| R7 | 等保内容外置 | 本地 `presets/dengbao.json` 保存当前全部分类模板与行业配置；由 `.gitignore` 排除，不被构建打包，不使用 skip-worktree；仓库内实现不再内置行业模板 |
| R8 | 普通用户能完成双端设置 | README 说明从界面导入、另存预设及桌面/Web 各导入一次；无需手写配置；新增弹窗具备标签、键盘操作、提交中状态和错误反馈 |

## 约束

- IndexedDB 的 onupgradeneeded 只建 store/索引，不遍历或迁移数据；摘要列表不能读完整项目。新字段不得破坏图片拆分、摘要原子维护或归档只读保护。
- 保留应用标识、桌面数据定位方式与 Web origin；本次不迁移实际用户数据。
- 使用 Trellis 与 TDD；验证只用隔离数据目录/浏览器库。
- 版本当前为 0.9.0；下一版本和发布需用户确认。本次不推送、不打标签、不发布。
- 不新增依赖，不扩展云同步、多预设库管理或分类删除/重排等需求。
