# 旧等保预设引导设计

## 边界与依据
仅修改预设识别、默认选择引导及相应测试，不迁移旧项目。现场未读取用户真实 Web 库；已知缺陷与只读复现见父任务 `../10-19-preset-group-experience/research/current-behavior.md`。

## 识别契约
- 继续使用 `legacyPresetFromDocument` / `getLegacyPresetCandidate` / `completeLegacyPresetOnboarding` 既有职责边界。
- 等保判据是已校验分类中完整包含八个历史等保核心 ID，且核心分类 type 正确；允许用户附加合法分类、改分类名或检查项。
- profile 缺省使用既有历史兼容值；显式 profile 必须合法，但不再以与 LEGACY_PROFILE 文本完全相同作为等保判据。自带等保报告标题和前缀必须可识别。
- 所有存量系统均须通过判定，不能只抽样一个系统。通用/等保混合、缺核心分类、异常数据或摘要/文档主键不一致时不提供自动继承。
- 所有模板不必完全相同。默认候选取这些等保系统中最近修改的合法模板；时间相同按 ID 稳定排序，选择规则不依赖数据库游标偶然顺序。
- 候选只含分类、检查项和 profile，无单位值、项目名、资产、图片或其他身份数据。提示按钮明确为“沿用最近等保模板”，不声称合并全部旧模板。

## 为什么采用最近模板
复用真实用户最近使用的等保配置，不额外塞入行业模板，不要求用户手写或重新导入 JSON。拒绝“模板有一项不同就不提示”，也不将各项目检查项强行合并。已有项目模板各自保留，新默认仅影响未来创建。

## 触发与资源生命周期
1. `ProjectList` 的摘要首屏成功渲染后，安排独立的延后只读检查；不把完整项目读取加入 `listProjectGroups`。
2. 先查 settings；存在显式 defaultPreset 或已完成引导记录时直接结束，不扫描完整文档。
3. 无设置才顺序逐条核对系统，禁止 `projects.getAll()`、图片 store 读取、并行持有全部文档。每步只保留模板投影。内联图片旧文档仍有逐条结构化克隆成本，不承诺恒定延迟或零图片字节分配。
4. 用户抢先点击新建时，复用或等待本轮检查，不重复扫描，也不在未判定时先创建通用系统。
5. 候选存在时复用既有引导 UI；进入列表触发不需要先打开创建表单。选择完成后，若没有主动新建，不自动弹出空创建表单。
6. 已有其他对话框时延后呈现引导，不叠加抢焦点。关闭/取消仅在当前挂载期抑制提示，不写持久完成记录；下一次主动新建可再次检查。
7. cleanup 取消计划中的检查、作废过期结果并释放可取消事务/连接；卸载和取消产生的 AbortError 不显示为业务失败。重试仅重跑必要检查。

## 写入与失败
- 继续使用 settings 同事务重查并写默认及完成标记，保留跨窗口已保存默认优先规则；不清除旧选择记录强制重新引导。
- 只有实际事务 complete 才报告完成；失败保留引导及重试，不能落入默认通用继续创建。
- 读取失败不记已完成；后台失败走既有中文 Toast/诊断机制，新建仍保留明确的读取失败与重试。
- 正常首屏列表只读摘要的契约不变；新增的是首屏之后、可取消的独立引导核对。需在最终 spec 更新中明确该区别并调整原“必须点击新建才核对”的旧约定。

## 兼容与回滚
无 DB 版本、预设 JSON version 或导出包格式变更。保存的默认仍能由旧版解析；回退代码不会撤销用户已经选择的默认，也不会改写任何旧项目。不自动回滚用户 settings。

## 影响文件
- `src/utils/preset.ts`：合法等保分类识别与模板投影。
- `src/utils/db.ts`：顺序核对、稳定候选选择、取消与连接释放。
- `src/components/ProjectList.tsx`：列表后触发、新建等待、代际与弹窗协调。
- `src/components/project-list/ProjectGroupDialog.tsx`：复用引导 UI 与准确按钮文案。
- `scripts/verify-presets.mjs`、`scripts/preset-browser-cases.mjs`、`scripts/verify-project-list-ui.mjs`：真实行为、事务和界面证据。

## 评审重点
不因 profile 文案漏判；不因检查项不同漏判；不覆盖显式默认；不并行加载大库；扫描失败不误称混合库；列表引导完成后不误建项目。
